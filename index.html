什么是 AIDLC？

AIDLC（AI-Driven Lifecycle）是一套 AI 驱动的软件开发全生命周期方法论，结合 BMAD（Build More Architect Dreams）— AI 驱动的敏捷开发框架，具有规模自适应智能，提供 12+ 专业化 Agent 和 34+ 工作流。

🎯

Inception（需求）

PM 创建 PRD，QA 编写测试策略。AI Agent 引导结构化思考。

⚡

Construction（构建）

PM、架构、开发、测试 4 角色并行。AI 生成代码和测试，人工 Review。

🚀

Operations（运维）

CDK 定义基础设施，CloudWatch 监控，IaC 确保环境一致性。

"AI is not Google. The AI is a facilitator — every module becomes a master facilitator to bring the best out of you."

—— Brian · BMAD 作者

🛠️ 环境准备 — Greenfield（新项目）

⚠️ 所有步骤必须按顺序执行，每步完成后验证再进入下一步

Step 1：检查前置依赖

node --version       # 必须 >= v20
python3 --version    # 必须 >= 3.10
uv --version         # 推荐，6.9 起为 Python 脚本标准
echo $GITHUB_TOKEN   # 应输出 ghp_...
❌ 版本不对？→ nvm install 20 / brew install python@3.12
❌ 无 uv？→ curl -LsSf https://astral.sh/uv/install.sh | sh
❌ 无 Token？→ GitHub Settings → Tokens → 勾选 public_repo

Step 2：创建项目 + 安装 BMAD 📖 文档

mkdir aidlc-bmad-workshop && cd aidlc-bmad-workshop
git init
npx bmad-method install
按提示选择：
• Modules → BMM + TEA
• AI IDE → kiro（推荐）/ claude-code / cursor / codex
• 语言 → Chinese · 项目名 → 你的项目名
💡 非交互式：npx bmad-method install --yes --modules bmm,tea --tools kiro

Step 3：通过提示词生成 Workshop 配置 关键

在 AI IDE 中输入内联提示词，让 AI 自动生成：
• _bmad/custom/*.toml — 4 个 Agent 定制配置
• _bmad-output/planning-artifacts/product-brief.md — 预置 Brief

提示词定义项目上下文（Hotel Booking API）、技术栈锁定、时间约束等，AI 据此生成完整配置。

Step 4：验证安装（必须全部 ✓）

ls _bmad/bmm/agents/   # ✓ 有 agent 文件
ls _bmad/custom/      # ✓ 有 4 个 .toml 文件
npx bmad-method status # ✓ 显示已安装模块
在 AI IDE 中输入 /bmad-help 确认可以正常响应。
❌ 失败？→ rm -rf _bmad/ 重新运行 npx bmad-method install

🛠️ 环境准备 — Brownfield（已有项目）

⚠️ 不要动已有代码！只在项目根目录叠加 BMAD，用内置 workflow 理解项目并生成上下文与架构

Step 1：验证现有代码健康

# 已有测试必须先跑通
npm test # 或 mvn test / pytest / go test

# git 状态必须干净
git status
❌ 测试失败 → 先修复再开始
❌ 有未提交变更 → 先 git commit 或 git stash

Step 2：安装 BMAD 📖 文档

cd your-existing-project
npx bmad-method install --yes --modules bmm,tea --tools kiro
⚠️ 只创建 _bmad/ 目录，不会修改已有文件

Step 3：用 BMAD 内置 skill 生成上下文与架构 关键

带自己的项目时不再用自定义提示词生成 *.toml，依次调用内置 workflow：
• bmad-document-project — 扫描代码库，输出项目文档
• bmad-generate-project-context — 生成 project-context.md
• bmad-architecture — 记录架构决策与扩展规则

Step 4：讲师带领审核 + 补充

• 审核 skill 产出（技术栈 / 架构 / 规模检测是否准确）
• 补充业务描述（项目做什么 / 本次加什么功能）
• 在 project-context.md 中标注受保护路径
• /bmad-help + /bmad-agent-pm 确认可用
✅ 上下文与架构文档已审核 + Agent 响应正常 → 开始 Workshop！

🛡️ Brownfield 项目注意事项

内置 workflow 生成的 project-context.md 记录技术栈与受保护路径约束，以下是额外提醒

🚫 AI 不可以做

• 删除/重命名已有文件
• 修改已有 API 格式
• 破坏性 schema 变更
• 引入冲突依赖
• 跳过 lint/test 规则

✅ AI 必须做

• 先读代码再动手
• 匹配已有代码风格
• 变更必须有测试
• 已有测试全部通过
• Feature Flag 包裹新功能

👤 你需要做

• 调用内置 skill 生成项目文档与上下文
• 审核 skill 产出 + 补充业务描述
• 在 project-context.md 标注受保护目录
• 开始前跑通已有测试
• Review Gate 更严格
💡 bmad-document-project + bmad-generate-project-context 扫描代码后把技术栈与约束写入 project-context.md，后续标准 Agent 自动加载。
你只需审核产出、补充业务描述、标注受保护路径即可。

👥 多人团队协作

核心原则：规划收敛、实施发散 — Phase 1-3 一人主笔，Phase 4 按 Epic 并行

分阶段策略

Phase 1-2（Analysis/PRD）：1 Tech Lead 主笔，团队评审
Phase 3（Architecture）：架构 + UX 可并行，Epic 拆分等二者完成
Phase 4（Implementation）：按 Epic 分配，每人独立 context

推荐：Epic 级分工

Epic 1 用户认证 → 开发者甲
Epic 2 订单管理 → 开发者乙
Epic 3 支付集成 → 开发者丙
✓ context 独立 · 冲突少 · 责任清晰

5 个必须同步的时机

1️⃣ PRD 完成 — 全员 review
2️⃣ Architecture 完成 — 全员 review
3️⃣ Sprint Planning — 认领 story
4️⃣ Epic Retrospective — Party Mode
5️⃣ Course Correction — 需求/架构变更

4 个反模式

❌ 多人各自跑 Mary 头脑风暴
❌ 每人写自己的 architecture.md
❌ A 写 story，B 直接改
❌ 多人共享同一 Agent 会话
推荐角色分配（3-6人）：1 Tech Lead（Phase 1-3 主笔）+ 2-4 开发者（Phase 4 分 Epic）+ 1 QA Lead（审全员 PR）

❓ 常见问题

必须使用 Kiro 吗？▶
推荐 Kiro（AWS AI IDE，内置 Spec Driven），但 Claude Code、Cursor、CodeX 同样兼容。核心差异在于 Kiro 的 Agent 协作和 Review 工作流更原生。
没有安装 BMAD 怎么办？▶
直接使用 Seed Prompt 文件中的内容，手动粘贴到 AI IDE。BMAD 安装是可选增强。
一个人可以扮演多个角色吗？▶
可以。使用 Party Mode 在同一终端切换不同 Agent。人数不足时建议兼任相近角色（如 PM + 架构师）。
Workshop 时间不够怎么办？▶
应急方案：① 砍掉 IaC ② 开发只完成 1 个 Story ③ 使用预置 PRD 跳过生成。确保至少完成一次"AI 生成 → 人工 Review"循环。
Kiro Spec Driven 和 BMAD 什么关系？▶
同一哲学的不同维度。Kiro 在 IDE 层面确保"先规格再代码"；BMAD 在方法论层面确保"Agent 引导逐层精化"。结合 = 从想法到规格到代码的完整闭环。
Agent 响应太慢或出错？▶
① 切换 Quick Flow（Barry Agent）② 检查 API Key 配额 ③ 准备离线 mock 数据 ④ Party Mode 绕过卡住环节。
Day 2 小组分享怎么准备？▶
每组 10 分钟：2min 项目概述 → 4min 产出物演示 → 2min Aha Moment / 踩坑 → 2min Q&A。建议提前准备屏幕录制或截图。
