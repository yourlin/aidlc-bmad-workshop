什么是 AIDLC？

AIDLC（AI-Driven Lifecycle）是一套 AI 驱动的软件开发全生命周期方法论，结合 BMAD 多 Agent 协作框架。

🎯

Inception（需求）

PM 创建 PRD，QA 编写测试策略。AI Agent 引导结构化思考。

⚡

Construction（构建）

开发、QA、测试、运维 4 角色并行。AI 生成代码和测试，人工 Review。

🚀

Operations（运维）

CDK 定义基础设施，CloudWatch 监控，IaC 确保环境一致性。

"AI is not Google. The AI is a facilitator — every module becomes a master facilitator to bring the best out of you."

—— Brian · BMAD 作者

🛠️ 环境准备 — Greenfield（新项目）

⚠️ 所有步骤必须按顺序执行，每步完成后验证再进入下一步

Step 1：检查前置依赖

node --version   # 必须 >= v20
python3 --version # 必须 >= 3.10
uv --version     # 可选
❌ 版本不对？→ nvm install 20 / brew install python@3.12

Step 2：创建项目 + 运行初始化脚本

mkdir aidlc-bmad-workshop && cd aidlc-bmad-workshop
git clone <repo-url> . # 或下载 zip
chmod +x setup-workshop.sh && ./setup-workshop.sh
✅ 脚本会自动创建 _bmad/ 配置 + seed prompts + product brief

Step 3：安装 BMAD Method 📖 官方文档

# 必须手动运行（脚本不会自动安装）
npx bmad-method install
按提示选择：
• Modules → BMM（核心框架）
• AI IDE → kiro（推荐）/ claude-code / cursor / codex
• 语言 → Chinese · 项目名 → 你的项目名

安装后 _bmad/custom/*.toml 中的 Agent 定制会自动生效：
PM 跳过 Analysis · 架构锁定技术栈 · 开发 TDD 模式 · QA 策略模板化
💡 非交互式：npx bmad-method install --yes --modules bmm --tools kiro
   其他 IDE：--tools codex / --tools cursor / --tools claude-code / --tools github-copilot

Step 4：验证安装（必须全部 ✓）

ls _bmad/bmm/agents/   # ✓ 有 agent yaml 文件
ls _bmad/manifest.yaml # ✓ 安装清单
npx bmad-method status # ✓ 显示已安装模块
❌ 失败？→ 删除 _bmad/ 重新运行 npx bmad-method install
⚠️ 如果 setup-workshop.sh 已创建 _bmad/，--yes 会走 quick-update 导致不完整。
   解决：先 rm -rf _bmad/ 再运行安装命令

🛠️ 环境准备 — Brownfield（已有项目）

⚠️ 不要动已有代码！只在项目根目录叠加 BMAD 配置

Step 1：在已有项目中安装 BMAD 📖 文档

cd your-existing-project

# 直接在已有项目根目录安装
npx bmad-method install
⚠️ BMAD 只会创建 _bmad/ 目录，不会修改已有文件
❌ 禁止：删除或移动已有文件 / 修改 package.json

Step 2：让 BMAD 生成项目上下文

# 在 AI IDE 中激活 PM Agent
/pm

# 选择 Create Product Brief（BP）
# Agent 会自动扫描代码库并追问你
# 产出 product-brief.md 含项目上下文
或者直接告诉 Agent：
"Analyze this existing codebase and create a product brief
that documents the current architecture, tech stack,
constraints, and areas I want to change."
💡 Agent 会自动读取代码结构，生成上下文文档，无需手动编写

Step 3：验证已有代码健康

# 已有测试必须先跑通
npm test # 或 mvn test / pytest / go test

# git 状态必须干净
git status # 只有 _bmad/ 是新增
❌ 测试失败 → 先修复再开始 Workshop
❌ 有未提交变更 → 先 git commit 或 git stash

Step 4：定制 Agent + 确认可用

# 修改 Agent 配置中的技术栈描述
vi _bmad/custom/bmad-agent-dev.toml
# 将 persistent_facts 中的技术栈改为你的实际栈
_bmad/custom/*.toml 中的 Agent 定制需要适配你的项目：
• 修改技术栈描述（如 Java/Spring 替换 TypeScript/Lambda）
• 追加 Brownfield 约束（不可修改的目录/接口）
• 在 AI IDE 中输入 /bmad-help 确认生效
✅ Agent 响应符合你的项目上下文 → 可以开始 Workshop！

🛡️ Brownfield 项目注意事项

Agent 定制配置（_bmad/custom/*.toml）已内置安全约束，以下是额外提醒

🚫 AI 不可以做

• 删除/重命名已有文件
• 修改已有 API 格式
• 破坏性 schema 变更
• 引入冲突依赖
• 跳过 lint/test 规则

✅ AI 必须做

• 先读代码再动手
• 匹配已有代码风格
• 变更必须有测试
• 已有测试全部通过
• Feature Flag 包裹新功能

� 你需要做

• 修改 *.toml 中的技术栈
• 追加受保护目录列表
• 用 /pm → BP 生成上下文
• 开始前跑通已有测试
• Review Gate 更严格
💡 这些约束已写入 _bmad/custom/*.toml 的 persistent_facts 和 principles 中。
Brownfield 项目只需修改技术栈描述 + 追加受保护路径，无需手写 Prompt。

❓ 常见问题

必须使用 Kiro 吗？▶
推荐 Kiro（AWS AI IDE，内置 Spec Driven），但 Claude Code、Cursor、CodeX 同样兼容。核心差异在于 Kiro 的 Agent 协作和 Review 工作流更原生。
没有安装 BMAD 怎么办？▶
直接使用 Seed Prompt 文件中的内容，手动粘贴到 AI IDE。BMAD 安装是可选增强。
一个人可以扮演多个角色吗？▶
可以。使用 Party Mode 在同一终端切换不同 Agent。人数不足时建议兼任相近角色（如 QA + 测试工程师）。
Workshop 时间不够怎么办？▶
应急方案：① 砍掉 IaC ② 开发只完成 1 个 Story ③ 使用预置 PRD 跳过生成。确保至少完成一次"AI 生成 → 人工 Review"循环。
Kiro Spec Driven 和 BMAD 什么关系？▶
同一哲学的不同维度。Kiro 在 IDE 层面确保"先规格再代码"；BMAD 在方法论层面确保"Agent 引导逐层精化"。结合 = 从想法到规格到代码的完整闭环。
Agent 响应太慢或出错？▶
① 切换 Quick Flow（Barry Agent）② 检查 API Key 配额 ③ 准备离线 mock 数据 ④ Party Mode 绕过卡住环节。
Day 2 小组分享怎么准备？▶
每组 10 分钟：2min 项目概述 → 4min 产出物演示 → 2min Aha Moment / 踩坑 → 2min Q&A。建议提前准备屏幕录制或截图。
